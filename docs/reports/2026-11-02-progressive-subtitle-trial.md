# 渐进式字幕试用检查（2026-11-02）

## 本次改变

沿用当前 NAudio 单音源采集、Whisper.net 本机识别、MyMemory 匿名联网翻译与 WPF 会话历史。连续语音累计约 0.8 秒后开始生成本机原文预览，之后约每 0.8 秒更新一次；预览队列只保留最新快照。语句定稿后的文字才发送给 MyMemory。上一句译文晚于下一句预览返回时，译文仍按语句 ID 进入历史，屏幕上的下一句预览不被覆盖。

设计和任务分解见[设计文档](../superpowers/specs/2026-11-02-progressive-subtitle-design.md)与[实施计划](../superpowers/plans/2026-11-02-progressive-subtitles.md)。

## 验证与实测

测试设备仍为当前 Windows x64 电脑，使用仓库 `artifacts/` 中的 Whisper small Q5_1 模型与已准备的中英文 WAV。计时从音频开始输入或默认扬声器开始播放算起，**不含首次 GPU 预热**；预览时间以会话事件为准，**不是屏幕实际绘制时间**。

| 场景 | 首个原文预览 | 在线译文完成 | 备注 |
| --- | ---: | ---: | --- |
| 英语 5.00 秒 WAV，约 100 毫秒分段输入 → 中文 | 1.62 秒 | 4.82 秒 | 快速/定时 PCM 输入；样本内停顿可让语句早于文件结束定稿 |
| 中文 5.67 秒 WAV，约 100 毫秒分段输入 → 英文 | 1.59 秒 | 7.43 秒 | 同上 |
| 英语 5.00 秒 WAV，从默认扬声器播放，经真实 WASAPI 回环 → 中文，第一次 | 1.56 秒 | 12.36 秒 | 只记录了总耗时，未分解联网请求 |
| 同一回环样本，第二次 | 1.57 秒 | 7.88 秒 | 播放在 6.02 秒结束；6.30 秒发起在线翻译，7.88 秒返回，联网阶段 1.58 秒 |
| 同一回环样本，第三次 | 1.62 秒 | 10.88 秒 | 播放在 6.02 秒结束；6.29 秒发起在线翻译，10.88 秒返回，联网阶段 4.59 秒 |

回环三次都产生了非空英文识别和非空中文在线译文，未出现网络警告。第二、三次的差异主要落在 MyMemory 请求耗时；第一次没有分段计时，不能确定其具体原因。上述数据表明**原文预览明显早于最终译文**，但最终译文延迟仍不稳定。这次试用不能宣称已经达到豆包类产品的低延迟体验或 30 分钟连续运行能力。

自动化验证：本次改造后 Release 编译 0 警告、0 错误；常规完整套件 179 通过、14 项因 Azure 凭据、本机音频或真实服务条件跳过；`dotnet format --verify-no-changes` 通过。真实中英分段输入测试和真实扬声器回环测试各单独通过。

## 候选软件对照限制

[LiveCaptions Translator v1.7.1300.1822](https://github.com/SakiRinn/LiveCaptions-Translator/releases/tag/v1.7.1300.1822) 的普通版和自带运行时版已下载并与发布页 SHA-256 核对。普通版因本机缺少 .NET 8 提示无法启动；自带运行时版由 Windows 应用控制启动时返回“应用批准超时”。目前没有候选软件的实际字幕或延迟数据，不能把其 README 功能描述当作对照实测。

本项目的新自包含验收包为 `artifacts/RealTimeTranslation-noazure-progressive-20261102-win-x64.zip`，相邻 `.sha256` 文件记录哈希。已解压核对 ZIP 与发布目录的可执行文件哈希一致；包内有 Windows x64 Vulkan 后端，没有 Azure SDK、模型权重、测试音频或日志。尝试启动解压后的程序时出现“实时翻译已经在运行”的单实例提示，说明当时已有同名程序占用互斥锁；这次未能直接检查新悬浮窗的实际绘制。

## 待验收

- 在启动的桌面试用包中肉眼检查预览底部行、历史追加、滚动、暂停与返回设置；本次自动化事件测试没有测量真实屏幕绘制。
- 用用户自己的电话/视频场景验证识别准确性和最终译文体感；尤其留意系统其他声音混入。
- 决定匿名翻译服务的额度和延迟波动是否可接受。若不能接受，需单独选择有明确服务承诺的在线翻译后端或自建服务，不能仅靠缩短本机分段解决。
