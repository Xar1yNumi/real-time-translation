## Microsoft runtime prerequisite found in review

An independent PE import audit found `MSVCP140.dll` required by 21 native files, `MSVCP140_1.dll` by ONNX Runtime, and `VCOMP140.dll` by six Whisper runtime files. None is present in the `r1` ZIP. The owner PC has signed Microsoft copies (version 14.50.35719.0), so its fresh-extraction test does not represent a Windows installation without the VC++ x64 runtime. **Do not upload `r1` as the public asset.**

On 2026-11-13, the owner chose the [official Microsoft Visual C++ Redistributable x64](https://aka.ms/vc14/vc_redist.x64.exe) as an installation prerequisite instead of redistributing Microsoft DLLs inside the ZIP. Microsoft's [deployment guidance](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files) recommends the central Redistributable for servicing and limits direct redistribution to licensed Visual Studio users. The final package must put this prerequisite in its README, release notes, and root `START-HERE.txt`, check the three DLLs at application startup, and repeat package verification. A clean Windows machine without the prerequisite has not been tested; the startup check is unit tested with simulated missing libraries.

## Rejected candidates and remaining native risk

The older `r4` ZIP passed an isolated 10-minute low-duty-cycle run in 625.878 seconds, but later repeated live tests exposed intermittent OpenBLAS allocator warnings inside the JSON pipe and one corrupted translation with its three-thread setting. `r4` and `r5` must not be published. The `r6` worker duplicates the protocol pipe and redirects native stdout before loading CTranslate2, and reduces intra-operation threads to two. No allocator warning entered the protocol in its worker tests or six diagnostic WAV runs. Its **single-threaded** OpenBLAS build nevertheless reports `Bad memory unallocation` in benchmark logs even with two CTranslate2 threads. **Do not upload `r6` as a public binary.** The threaded OpenBLAS rebuild and its acceptance results are recorded above.

## Scope and limitations

The public package supports Chinese↔English only, capturing the default system playback stream or a microphone. It does not isolate individual applications or speakers. Music and background noise can reduce recognition accuracy. OPUS-MT output varies with CPU parallelism and can omit part of a sentence; tests check direction and readable meaning, not exact wording. The owner waived live microphone testing. Physical network disconnection and a 30-minute high-duty-cycle run have not been measured; translation itself uses local components.

The source repository includes historical notes about an older, private Intel-based audit candidate. That candidate is not the public release binary.
