# 渐进式字幕与会话累计设计（2026-11-02）

## 决策与目标

项目负责人已同意保留现有 .NET/WPF 工程，先改善字幕及时性，再依据实测决定是否替换识别后端。首版以中英互译可用为验收重点；现有俄语能力不删除。当前单音源、免账号/密钥、联网文本翻译和 MIT 项目结构保持不变。

目标是说话过程中显示可更新的**原文预览**，不等 600 毫秒尾静音或 8 秒强制分段；语句定稿并获得在线译文后，将原文和译文**追加到整场会话历史**。预览文字可能被后续识别修正，只有定稿译文进入历史。匿名 MyMemory 不接收每次预览，避免重复消耗额度。

## 方案取舍

1. **采用：现有 Whisper 模型对当前语句做有限频率快照识别。** 继续用 NAudio 单音源及有界缓冲；语音累计足够长时每隔约 1 秒产生最新快照，本机识别后覆盖当前预览。语句定稿仍走现有在线翻译。单独的预览任务不等待 MyMemory 响应；同一识别器内部串行，定稿任务优先，旧快照可取消。成本是每句重复少量本机推理；CPU 回退时需以最新快照覆盖旧快照，不能无限排队。
2. Windows 11 实时字幕作为识别后端：可能更早产生原文，但只能直接抓取系统音频，麦克风为附加选项，且依赖 Windows UI Automation；本次不接入。
3. WhisperLive 独立服务：流式能力成熟，但增加 Python 服务、模型和安装复杂度；先不整体迁移。

## 数据流与边界

```text
单音源 PCM -> PcmUtteranceSegmenter
  -> 最新语句快照（内存仅保留最新一份） -> 本机 Whisper -> 当前原文预览
  -> 定稿语句（现有最多两项队列） -> 本机 Whisper -> MyMemory -> 完成字幕
  -> 历史列表按语句 ID 去重追加；新语句预览不抹掉旧语句的迟到译文
```

- 分段器为同一句的预览与定稿提供稳定的内部语句编号；会话层将其映射到既有 `UtteranceId` 和递增 `Sequence`。不跨会话复用。
- 预览输出只允许更新当前未定稿语句；较旧、被取消或已定稿的预览不能回流。停止、暂停或新会话启动后旧任务不能修改字幕。
- 定稿完成可能晚于下一句预览。协调器仍应把这个旧句译文交给会话历史，但不能把屏幕上正在说的较新原文覆盖掉。
- 预览路径不调用 MyMemory；原有用户文字发送确认、配额、网络错误和重试逻辑保持。
- 与原有行为兼容：没有足够语音的噪声不出现预览；静音与无声不创建历史；同语种字幕仍显示原文与提示；积压仍可见且有界。

## 验收

1. 自动化测试证明 2 秒连续语音在未到尾静音前产生至少一次预览，后续快照沿用相同语句 ID，定稿也沿用该 ID。
2. 在翻译请求尚未返回时，下一句预览仍能出现；旧句译文随后进入历史且不覆盖下一句预览。预览不发起在线翻译。
3. 停止、取消、积压和同语种路径的现有测试继续通过；Release 编译、解决方案测试及格式检查通过。
4. 使用已准备的中英音频样本记录从音频进入到首个预览、语句定稿和译文完成的时间。测试数据须注明是否为快速 PCM 注入，不能称为真人说话到屏幕的端到端延迟。

## 候选软件对照状态

`LiveCaptions Translator` v1.7.1300.1822 的 x64 普通版和自带运行时版均从其 GitHub 发布页下载，SHA-256 与发布页元数据一致。普通版因缺少 .NET 8 无法启动；自带运行时版通过 Windows 应用控制启动时返回“应用批准超时”。因此候选软件尚无实际延迟或稳定性结果，不以源码推测代替体验对照。下载物仅存放在 git 忽略的 `artifacts/comparison/`。
